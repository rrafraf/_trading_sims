Plain meaning

What did we actually prove?

For simple bar strategies, Backtrader, VectorBT, PyBroker, and muni can all run through the same benchmark harness. Muni is now connected without merging repos.

The judge was tightened after OG found a false-match bug. It now compares final cash, position, every fill, prices, fees, and timestamps, not only final equity.

Dirty candle data is now rejected by default before strategy generation. A dirty-data test can still be allowed on purpose when the test is about dirty-data behavior.

It does not yet prove that any of them model real broker fills perfectly. It proves they can agree when we force the same simple rules.

The experiment pipeline

1. Same dataEach simulator receives the same OHLCV bars.
2. Same strategyShared code creates target positions.
3. AdapterThin translator sends orders into each simulator.
4. Same result shapeFills, cash, position, and equity are normalized.
5. CompareIf results differ, we classify why.

Best fit by trading style

If the strategy is... Use first Why
1-minute indicators, simple market entries/exits Backtrader or PyBroker Enough realism for bar-level logic and easy to debug.
Trying thousands of parameter combinations VectorBT Built for fast matrix/grid-style research.
Alpaca data plus ML or walk-forward testing PyBroker Designed around data sources, model workflows, and walk-forward analysis.
Serious broker/order model comparison LEAN, after runner work Most serious all-around engine, but heavier to wire into this harness.
Market making, passive limits, queue position, latency Nautilus/HftBacktest/QuantReplay/ABIDES These need tick/order-book/generative market data, not only candles.
Important limitation

What this still does not answer

We have not yet tested stop orders, limit orders, same-candle stop/target ambiguity, broker-specific paper fills, market impact, latency, or queue position. Those are the next stress tests.

Glossary without the fog

AdapterA translator between our shared strategy format and one simulator's API.
Bar / candleA compressed time slice: open, high, low, close, and volume.
1-minute strategyA strategy that makes decisions using one-minute bars.
FillThe simulated execution of an order: time, price, quantity, and fee.
SlippageThe price penalty between the price you hoped for and the price you got.
Reference baselineOur simple control model. Other simulators should match it on simple cases.
MicrostructureThe detailed market mechanics inside the candle: order book, queue, trades, latency.
Paper tradingA broker API sandbox. Useful for API behavior, not a perfect model of real fills.
